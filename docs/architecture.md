### 1. 运行时基座与插件生命周期

整个系统建立在依赖注入容器之上，所有功能模块都以插件形式挂载到统一运行时中。通过上下文对象获取生命周期能力，包括初始化、配置加载、服务注册和销毁。后端分析、前端界面、代码索引等模块共享同一个运行时环境，彼此通过声明式依赖进行组合调用。

### 2. 协议层：跨边界远程调用

系统需要跨越进程或插件边界传递指令与数据，因此抽象出一套远程调用协议。核心机制是「网关绑定」与「远程调用标记」：任何服务方法都可以被标记为可远程调用，并绑定到网关上的特定端点。调用方无需关心目标是在本地还是远端，只需要像调用本地方法一样发起请求即可。同时，协议层将查找失败等异常情况显式建模，保证远程交互的错误可预期、可处理。

### 3. 源码索引：获取代码事实

架构分析的第一步是将原始源码转化为结构化事实。这一层负责探测源码语言、发现包根目录、递归收集源文件，并通过语法树解析器提取导入关系、类型声明、函数与类定义等代码实体。解析结果被统一建模为代码索引结果，其中包含包、实体、导入依赖、语言类型等信息。这一层屏蔽了不同语言的语法差异，为上层提供一致的数据来源。

### 4. 架构分析与知识抽取

在获得代码索引后，分析引擎开始对工作区或具体包进行架构重建。它分析包与包、模块与模块之间的依赖关系，形成架构拓扑，并进一步提炼出高层的概念节点。这些概念节点代表了架构中的关键组件、模块边界或设计模式。与此同时，分析流程还会识别与架构相关的文档材料，从文档树中抽取候选片段，并基于缓存避免重复计算，最终生成结构化的架构知识。

### 5. 生成与可视化交付

分析得到的架构知识需要被转换为用户可理解的可视化形态。系统提供一条从分析流程到视图配置的生成链路：内部模型被转换为架构视图配置，前端基于该配置渲染图表。渲染层维护 Mermaid 状态和用户选择状态，通过核心事件驱动界面更新，实现交互式的架构图、序列图等展示。用户的选择会反馈到核心状态中，并可能触发新一轮的分析或细节展开，形成闭环。

### 6. 统一实体模型贯穿全流程

上述所有步骤通过一套共享的实体模型进行数据交换。代码实体、概念节点、序列消息、核心事件、视图配置、选择状态等，既是进程间通信的载荷，也是前端 UI 状态的基础。这一模型确保分析结果从后端到前端传播时语义不丢失，并且让不同模块可以基于同一套语言协作。

1. 用户在 `client-arch-lens` 界面触发“分析工作区”操作，传入工作区路径或包路径。
2. `client-arch-lens` 通过 `@deepseek-ai/cordis` 向 `arch-lens-backend` 发起 `analyzeWorkspace` 调用；若跨越进程边界，则由 `typert-protocol` 的 `RemoteInvocationMarker` 完成远程方法封装与路由。
3. `arch-lens-backend` 入口 `src/index.ts` 接收到请求后，调用 `code-index` 提供的能力，对目标工作区进行源码索引。
4. `code-index` 委托 `code-index-tree-sitter` 执行具体解析：先 `detectLanguage` 识别语言，再 `discoverPackageRoots` 发现包根，`listDirs` 遍历目录，`collectSources` 收集源码文件，并通过 `resolveUnder`、`fileExists`、`dirExists`、`relPath` 处理路径关系。
5. `code-index-tree-sitter` 使用 tree-sitter 解析源码，产出 `CodeEntity`、`CodeImport`、`CodePackage`，最终由 `code-index` 汇总为 `CodeIndexResult` 返回给 `arch-lens-backend`。
6. `arch-lens-backend` 拿到 `CodeIndexResult` 后，按需调用 `analyzePackage` 细化包级结构，并使用 `cacheName` 进行结果缓存。
7. `arch-lens-backend` 通过 `detectArchDocs` 发现架构相关文档，使用 `extractDocTree` 抽取文档树，同时生成 `docCandidates` 作为候选文档。
8. `arch-lens-backend` 调用 `generateFromFlow`，将源码索引结果与文档树融合，转换为 `ConceptTreeNode` 语义树。
9. `arch-lens-backend` 将 `ConceptTreeNode` 作为响应，通过 `typert-protocol` / cordis 事件通道返回给 `client-arch-lens`。
10. `client-arch-lens` 更新 `CoreState` 与 `MermaidState`，利用 React 渲染 `ConceptNode`、`SequenceMessage` 等视图模型，再通过 mermaid 生成架构图，最终呈现给用户。

## 概念层级

## 概念层级

### 代码索引与语法解析机制
项目首先通过底层的语法解析能力对源代码进行扫描，识别语言类型、目录结构和源码文件集合，进而提取出代码包、导入关系、代码实体等结构化信息。这一层为上层分析提供了统一的代码模型基础，使得不同类型的项目都能被转化为可处理的结构化数据，从而支撑后续的架构判断。

### 架构概念建模机制
在代码索引的基础上，系统对工作区与包进行深入分析，将底层的代码实体归纳为高层架构概念。概念树节点（ConceptTreeNode）是这一层的核心表达，它承载系统的高层组件与关系，使架构信息从符号级跃升为可展示、可推理的概念级。该机制是连接静态代码与业务架构认知的关键桥梁。

### 架构文档生成与演进机制
系统能够检测已有的架构文档，并解析其文档树结构，同时结合概念树生成新的文档候选。通过缓存机制避免重复分析，通过生成流程将代码分析结果转化为人类可读的架构描述。这一过程实现了从代码到文档的半自动化演进，帮助架构知识随代码变化而持续更新。

### 客户端可视化与交互机制
客户端模块负责将架构概念树渲染为可视化图形，基于 Mermaid 状态与核心状态管理当前视图，并提供架构配置与交互属性。用户可以通过选择状态、时序消息等实体与架构图互动，既能看到宏观架构，也能深入具体组件或调用序列，实现多粒度的架构浏览。

### 远程协议与跨模块协作机制

项目首先通过底层的语法解析能力对源代码进行扫描，识别语言类型、目录结构和源码文件集合，进而提取出代码包、导入关系、代码实体等结构化信息。这一层为上层分析提供了统一的代码模型基础，使得不同类型的项目都能被转化为可处理的结构化数据，从而支撑后续的架构判断。

### 架构概念建模机制
在代码索引的基础上，系统对工作区与包进行深入分析，将底层的代码实体归纳为高层架构概念。概念树节点（ConceptTreeNode）是这一层的核心表达，它承载系统的高层组件与关系，使架构信息从符号级跃升为可展示、可推理的概念级。该机制是连接静态代码与业务架构认知的关键桥梁。

### 架构文档生成与演进机制
系统能够检测已有的架构文档，并解析其文档树结构，同时结合概念树生成新的文档候选。通过缓存机制避免重复分析，通过生成流程将代码分析结果转化为人类可读的架构描述。这一过程实现了从代码到文档的半自动化演进，帮助架构知识随代码变化而持续更新。

### 客户端可视化与交互机制
客户端模块负责将架构概念树渲染为可视化图形，基于 Mermaid 状态与核心状态管理当前视图，并提供架构配置与交互属性。用户可以通过选择状态、时序消息等实体与架构图互动，既能看到宏观架构，也能深入具体组件或调用序列，实现多粒度的架构浏览。

### 远程协议与跨模块协作机制
项目各模块之间存在跨进程或跨包调用的需要，因此通过协议层定义远程方法标记、初始化上下文与调用标记等规范，使得前端、后端、索引器、分析器之间可以解耦协作。该机制让各个模块像独立服务一样协同工作，提升了整个系统在复杂插件环境中的可扩展性与可维护性。

### 5. 生成与可视化交付

分析得到的架构知识需要被转换为用户可理解的可视化形态。系统提供一条从分析流程到视图配置的生成链路：内部模型被转换为架构视图配置，前端基于该配置渲染图表。渲染层维护 Mermaid 状态和用户选择状态，通过核心事件驱动界面更新，实现交互式的架构图、序列图等展示。用户的选择会反馈到核心状态中，并可能触发新一轮的分析或细节展开，形成闭环。

### 6. 统一实体模型贯穿全流程

上述所有步骤通过一套共享的实体模型进行数据交换。代码实体、概念节点、序列消息、核心事件、视图配置、选择状态等，既是进程间通信的载荷，也是前端 UI 状态的基础。这一模型确保分析结果从后端到前端传播时语义不丢失，并且让不同模块可以基于同一套语言协作。

1. 用户在 `client-arch-lens` 界面触发“分析工作区”操作，传入工作区路径或包路径。
2. `client-arch-lens` 通过 `@deepseek-ai/cordis` 向 `arch-lens-backend` 发起 `analyzeWorkspace` 调用；若跨越进程边界，则由 `typert-protocol` 的 `RemoteInvocationMarker` 完成远程方法封装与路由。
3. `arch-lens-backend` 入口 `src/index.ts` 接收到请求后，调用 `code-index` 提供的能力，对目标工作区进行源码索引。
4. `code-index` 委托 `code-index-tree-sitter` 执行具体解析：先 `detectLanguage` 识别语言，再 `discoverPackageRoots` 发现包根，`listDirs` 遍历目录，`collectSources` 收集源码文件，并通过 `resolveUnder`、`fileExists`、`dirExists`、`relPath` 处理路径关系。
5. `code-index-tree-sitter` 使用 tree-sitter 解析源码，产出 `CodeEntity`、`CodeImport`、`CodePackage`，最终由 `code-index` 汇总为 `CodeIndexResult` 返回给 `arch-lens-backend`。
6. `arch-lens-backend` 拿到 `CodeIndexResult` 后，按需调用 `analyzePackage` 细化包级结构，并使用 `cacheName` 进行结果缓存。
7. `arch-lens-backend` 通过 `detectArchDocs` 发现架构相关文档，使用 `extractDocTree` 抽取文档树，同时生成 `docCandidates` 作为候选文档。
8. `arch-lens-backend` 调用 `generateFromFlow`，将源码索引结果与文档树融合，转换为 `ConceptTreeNode` 语义树。
9. `arch-lens-backend` 将 `ConceptTreeNode` 作为响应，通过 `typert-protocol` / cordis 事件通道返回给 `client-arch-lens`。
10. `client-arch-lens` 更新 `CoreState` 与 `MermaidState`，利用 React 渲染 `ConceptNode`、`SequenceMessage` 等视图模型，再通过 mermaid 生成架构图，最终呈现给用户。

## 核心交互

- **请求架构分析**：`client-arch-lens`（生产者）→ 调用 `analyzePackage` / `analyzeWorkspace` → `arch-lens-backend`（消费者）执行分析，返回 `ConceptTreeNode` 与 `docCandidates`。

- **代码索引**：`arch-lens-backend`（生产者）→ 通过 `code-index` 的 `CodeIndexResult` 发起索引请求 → `code-index-tree-sitter`（消费者）调用 `detectLanguage`、`collectSources` 等解析源码，生成 `CodePackage` / `CodeEntity` 回传给后端。

- **前端状态更新**：`arch-lens-backend`（生产者）→ 发出 `CoreEvent`（例如分析完成事件）→ `client-arch-lens`（消费者）接收后更新 `CoreState`，并根据 `MermaidState` 渲染架构图。

- **远程方法调用**：`client-arch-lens`（生产者）→ 通过 `typert-protocol` 的 `RemoteInvocationMarker` 发起远程调用 → `arch-lens-backend`（消费者）通过 `TypertGatewayBinding` 暴露并响应具体的分析服务。

- **缓存复用**：`arch-lens-backend`（生产者）→ 使用 `cacheName` 作为缓存标识存储分析结果 → 后续请求或 `client-arch-lens`（消费者）可直接读取缓存，避免重复计算。
