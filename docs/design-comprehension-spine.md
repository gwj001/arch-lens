# 设计备忘：理解主干（Comprehension Spine）

> **状态**：共识草案——V2 设计主线，**未实现**。源自 2026-09 的连续讨论，收编并扩展
> CHANGELOG V2 清单第 ⑧⑨ 条。
> **与现有代码的关系**：不改动 V1 任何行为。落地时分阶段推进，每一阶段都不得破坏
> `版本信封 / 统一写路径 / 两段式失效` 三件套。

---

## 一、问题

V1 的图与文档生成在四个维度上偏离"人如何理解代码"：

1. **顺序是分类学的，不是认知的**。生图注册表与章节顺序均为
   概念→流程→时序→交互→依赖→ER→目录。现成反例：职责总结（词汇表）排在最后，
   而图提示词要用职责（`mergeDutyFacts`）——词汇表没建就先造句。
2. **节点互不消费**。7 章是独立射击；图与章之间、图与图之间没有结论传递
   （唯一例外是职责→图这一根线）。
3. **过期缓存 = 垃圾**。版本失配即拒绝、从头再生成；而人重读代码是问
   "上次以来变了什么"。
4. **成本集中一次付清**。全量出文档实测 18 分钟（8 次串行调用，思考链主导）；
   学习本来是分摊的、增量的。

理念一句话：**文档与图应该沿着理解的路径生长，而不是按维度平铺。**

---

## 二、策略依据：理解一个代码仓库的真实顺序

（本节是整个设计的地基，与具体实现无关。）

| 阶段 | 动作 | 产出的心智模型 |
|---|---|---|
| 0 定向 | README / manifest / 目录形状；仓库自带文档当"声称"读 | 预期（不是结论） |
| 1 找心跳 | 入口（main/server/cli/订阅点）——外部世界与机器的接缝 | 触发词汇表 |
| 2 黄金路径 | 选一个最典型触发，**深度优先**走到底："当 X 进来时发生什么？" | 骨干模块 + 主干/枝叶分界 |
| 3 骨架 | 回看依赖图：静态边 = "能发生什么"，走过的路径 = "真发生什么"；找所有东西都经过的"窄腰" | 分层与缝 |
| 4 名词 | 核心实体的生命周期（在哪生、在哪变、在哪死）——系统存什么 = 系统是什么 | 状态模型 |
| 5 反应 | 事件/钩子/监听器——调用图上看不到的神经系统 | 行为模型 |
| 6 合成 | 概念抽象是理解的**终点**，不是起点 | 概念层级 |

两个辅助习惯：读测试（可执行的意图声明，比注释诚实）；读错误处理
（失败路径暴露真实不变量——代码在防什么，什么就是命脉）。

**关键推论**：概念层级在认知序里出现两次——"读声称"（阶段 0，趁早）与
"做合成"（阶段 6，趁晚）。任何重排都必须分开对待这两个身份，不能一刀切。

## 三、核心模型：主干 × 节点解析

### 3.1 主干（一次建立，全局共享）

主干 = 理解路径的节点序列，每个节点对应一个 tab/图/章节。顺序按第二节的认知序：

```
词汇 ──► 声称 ──► 主角 ──► 黄金路径 ──► 反应 ──► 合成
职责/目录   文档优先提取   核心选择      时序+流程     交互      概念(合成态)
```

- 时序与流程是**同一条黄金路径的两种投影**，相邻生成、可互喂；
- `analysis.ts` 共享档案（两次 LLM 出 `coreIds + conceptTree + flow +
  seqMessages + events`）就是主干的雏形——"理解一趟、渲染多次"的骨架已在，
  缺的只是把它当主干用（顺序语义 + 结论传递）；
- 主干是**生成顺序与提示词语境**的载体，不新增缓存种类。

### 3.2 节点解析梯度（"找最新版，没有就延伸查找"）

轮到主干上某个节点时，按梯度贪心解析：

| 梯度 | 来源 | 成本 | 现状 |
|---|---|---|---|
| ① 最新有效缓存 | `v === factsVersion` 且 deps 满足 | 0 | **已有**（版本信封） |
| ② 过期缓存 → **先前稿** | 失配缓存不丢弃，作为增量修订的底稿 | 低 | **新增**（§四.1） |
| ③ 文档原文提取 | 声称，权威（`doc` 徽章） | 0 | **已有**（文档优先链） |
| ④ 上游结论 + 共享档案 | 主干前序节点的结论作为事实入提示词 | 0 | 仅职责→图一根线（§四.2） |
| ⑤ LLM 生成 | 提示词携带 ②③④ 全部语境 | 高 | **已有**（链尾兜底） |

"找最新版" = ①；"延伸查找" = ②③④ 逐级外扩；⑤ 永远是最后兜底。

### 3.3 级联语境

上游节点的结论进下游提示词：黄金路径确立后，交互/依赖/ER 章的提示词不再是
全量包清单平铺，而是"**主角 + 已确立的路径** + 全量仅作兜底"。章节管线同理：
依赖章引用黄金路径的发现，ER 章引用路径触及的实体——出来的不是一叠散文，
是一份有叙事的文档。

## 四、三件真正的新增

### 4.1 过期缓存降级为"先前稿"（增量修订）

- 失效语义从"拒绝"改为"降格"：过期图/章作为 prior 喂回，提示词改成
  "以下是上一版，事实已变化（变化点：……），请**只修订受影响部分**"；
- 收益：提示词更小、输出更稳（diff 友好）、费用更低，且天然压缩思考链
  （任务从"创作"变"修订"）——这是独立于思考档的又一根提速杠杆；
- 约束：修订结果**必须**走同一幻觉门禁、同一统一写路径、盖同一版本戳；
- 风险与对策：先前稿可能锚定旧错误 → 门禁照旧拦截；`🔁 全量重建`
  永远保留为逃生门（不走先前稿）。

### 4.2 上游结论进下游提示词

主干节点的产出（核心选择、黄金路径的消息序列、已确立的边界）作为**事实段**
注入下游提示词，与既有【事实】块同一格式、同受门禁约束（上游结论本身来自
事实，传递不引入新幻觉面；但下游引用上游的包名/边仍会被门禁复核）。

### 4.3 级联依赖记进信封

- 节点 B 消费了节点 A 的结论 ⇒ B 的信封 `deps` 扩展为
  `{ packages: [...], requires: [{ node: 'seq', v: 123 }] }`；
- A 失效（代码变动或强制重建）⇒ `selectiveInvalidate` 沿 `requires`
  级联失效下游——现有两段式失效是它的底座，加一段"主干段"即可；
- **这与细粒度失效（V2①）是同一本账**：级联越深，失效账越要算细，
  必须一起设计，不能分两次改信封格式。

## 五、讲解版本化的归位

（原 V2⑧。在本框架里它不是独立功能，而是章节节点的另一个"最新版"来源。）

- 讲解回答埋令牌（figId 同款捕获机制），宿主落版本信封
  `.arch-lens-explain-<章>-<语言>.json`，`deps` = 该图的 `figureDeps`
  （图失效连带讲解失效）；
- 章节节点的解析梯度因此插入一格：**新鲜讲解（文档语体写就 → 零二次 LLM）
  → 图证生成 → 延伸**；讲解提示词直接按书面文档语体要求，省掉"讲解维度
  → 文档维度"的二次归纳调用；
- 缺失/过期回落现有宿主直连生成（一键仍能跑完）；
- 效果：出文档成本摊进学习时间——学习过的章节，文档白得。

## 六、与提速的关系

| 杠杆 | 机制 | 与本设计的关系 |
|---|---|---|
| 讲解版本化（§五） | 成本从"文档生成时"挪到"学习时" | 本设计的组成部分 |
| 先前稿增量修订（§四.1） | 任务从创作变修订，提示词与思考链同步缩小 | 本设计的组成部分 |
| docs 类调用降思考档 | `prepareCall` 提案模型支持的最低档 | 正交，可独立先做（V2⑨） |
| 并行化 | 墙钟 ≈ 最慢一节点 | 与主干哲学相抵：级联语境要求串行；仅在**同层无依赖节点**（如流程两视角）内可选 |

注意：首轮全量（无任何缓存、无讲解）的总账不会归零——总得有人付理解的钱。
本设计改变的是**付钱的方式**（分摊、增量、可复用），不是总量。

## 七、与现有机制的兼容性

- **版本信封**：不变，仅扩展 `deps` 语义（§四.3）；
- **统一写路径**（`writeFigure` / `writeVersionedCache`）：不变——先前稿
  修订、级联产物、讲解落盘全部经此一口；
- **两段式级联失效**：不变，追加"主干段"（§四.3）；
- **幻觉门禁**：不变，且适用范围自然扩大（修订产物、级联产物同样过门禁）；
- **文档优先链**：不变——"读声称"节点保持零 LLM 优势，重排不得破坏；
- **`.generated.md` 后缀与 `docs/architecture.md` 保留区**：不变；
- **V1 一键**：保留为主干的用户入口——主干是 V1 的重排与增强，不是推翻。

## 八、分阶段落地建议

> 进度：✅ = 已实施（本仓提交）；其余为设计目标。

| 阶段 | 内容 | 改动面 | 独立价值 | 状态 |
|---|---|---|---|---|
| 0 | 主干重排：注册表/章节顺序按认知序；职责提前到首位 | 数组顺序 + 职责补建时机 | 立即消除"无词汇表先造句" | ✅ `FIGURE_SPECS`=duties→concepts→core→seq→flow×2→interaction；`DOC_CHAPTER_KINDS`=catalog→concepts→deps→seq→flow→er→interaction |
| − | docs 思考档下调：`docs` 类 `llmText` 提案路由广告的最低思考档 | `docsgen.ts lowestReasoningEffort` | 正文是受限结构化任务，思考链曾占墙钟 ≈90% | ✅ 仅提案路由已广告的能力，查询失败回落默认 |
| 1 | 过期缓存当先前稿：图与章的增量修订链 | 各链读侧 + 修订提示词 | 最值钱的单项（提速+稳态） | 未实施 |
| 2 | 级联语境 + `requires` 信封账 | 提示词组装 + 信封格式 + 失效主干段 | 与细粒度失效同批交付 | 未实施 |
| 3 | 讲解版本化归位（§五） | 捕获令牌 + 讲解信封 + 章节解析梯度 | 文档成本摊进学习 | 未实施 |

每阶段独立可发布、独立可回滚（回滚 = 顺序翻回 / 信封 `requires` 忽略 /
讲解信封不读）。任何阶段全绿门槛不变：`pnpm typecheck` + 全量 vitest + 三面构建。

## 九、已知取舍

1. **级联深度 ↔ 失效账复杂度**：级联越深，`requires` 图越密；用
   "主干段"统一处理，避免逐图特判。
2. **先前稿锚定风险**：旧错误可能沿修订存活——门禁 + 全量重建逃生门兜底。
3. **声称与合成的双重身份**：概念节点在阶段 0（读）与阶段 6（合成）各出现
   一次，重排实现时必须显式区分，否则文档优先链的零 LLM 冷启动会被破坏。
4. **串行是特性不是缺陷**：⏹ 可中断、⚙️ 状态直播、费用可预测、级联语境可用；
   并行只在同层无依赖节点内考虑。
