## 专项一：图失效粒度——事实指纹重验（facts fingerprint revalidation）

### 背景

- 现状：图缓存信封 `{v, deps, data}` 的 `deps` 记账到**包**为止；失效判定是
  `deps ∩ 变动包 ≠ ∅`（`selectiveInvalidate`）。「变动文件 → 所属包」的归并只发生在
  重扫链上半段（`computeChangedPackages`），**没有**「图 → 文件」的记账步骤。
- 后果：**过度失效**——deps 含某包的图，会因该包内任何文件变动（哪怕注释）被打墓碑，
  下次读取走 LLM 重建。包粒度是安全方向（漏失效 = 错误数据；过度失效 = 多花钱），
  V2①（章节细粒度包依赖）已收割了包内的安全收窄（章节 → 包子集、ER → 实体所属包、
  「仅函数实现变化不失效 ER 章」）。
- 已论证并否决的路线：**图 → 文件记账**（deps 记文件集合）。难点不在存储——加字段
  便宜、旧信封回落包级即可——而在**判定**：要准确回答「这张图依据了哪些文件」必须从
  导出事实反推源文件（按图按边做 import 可达性分析），是一套全新管线；且多数图消费
  **聚合事实**（包清单 / 调用边表 / 消息序列），端点包内任何文件的 import 变化都可能
  改变聚合，文件级收窄空间天然受限，最终往往退化回包级。成本大、收益存疑，不取。

### 方案：事实指纹重验

信封多存一个 `factsHash`（生成时该图**事实块**的稳定摘要）。重扫后对失效判定命中的
信封做**零 LLM** 重验：

```
selectiveInvalidate 命中（deps ∩ 变动包 ≠ ∅）
        │  不再直接打墓碑
        ▼
零 LLM 重建该图的事实块 → 比对 factsHash
        ├─ 一致 → 重盖章保留（无论动了多少文件：注释、局部重构、不碰事实面的
        │          改动都不再杀图）
        └─ 不一致 → 打墓碑，下次读取走 LLM 重建（现状路径）
```

事实指纹**取代**文件级 deps 的全部价值：文件粒度只是「事实未变」的一个代理指标，
直接比对事实本身更准也更省——任何「没改变事实」的改动自动不再触发重建。

### 实现要点

1. **事实块重建通道**：各图生成路径已在组装事实块（包清单 / 调用边表 / 职责 /
   实体清单……），抽成「按 kind 重建事实块」的可复用纯函数，供生成与重验两端共用
   （同源 ⇒ 判定可信）；
2. **信封 schema** 加 `factsHash`：旧信封无此字段 → **回落现状**（按 deps 判定直接
   墓碑，不重验）——渐进迁移，无需一次性刷缓存；
3. **挂点**：`selectiveInvalidate` 的「相交 → 墓碑」分支替换为「重验」；未相交分支
   维持重盖章不变（deps 未相交 ⇒ 事实源未动，无需重验——V2① 的同源收窄保证这一点）；
4. **时间盒**：大仓批量重验不能卡住重扫 RPC——参照 `ensureIndexEnvelope` 的
   race + timebox 模式，超时部分转后台继续，重扫照常返回；
5. **确定性前提**（主要审计成本）：事实块内不得含不稳定内容（时间戳、随机顺序、
   未排序的 map 迭代）。职责总结 / 文档逐字提取均为落盘稳定产物，调用边表来自代码
   索引（确定）；需逐 kind 审一遍事实块组装函数，做排序归一。

### 工作量

- 重建通道 + schema + 挂点：中等，一次专注迭代；
- 逐 kind 确定性审计 + 测试：**主要成本**。现有失效语义测试
  （requires-cascade / selective-invalidate / change-pack）需扩「事实未变 → 不失效、
  零 LLM」用例族。

### 风险与边界

- 方法级（-methods）变体的事实面更细（file:line 证据），是否纳入重验需单独评估，
  可作为第二期；
- 动态下钻图与用户保存的动态图（`.arch-lens-draw-*`）不在注册表失效体系内，本专项
  不覆盖，维持现状；
- 幻觉门禁 / 先前稿修订链不受影响——重验只决定「保留 vs 重建」，不改任何写路径；
- 重验本身零 LLM，不存在「后台偷偷花钱」面。

### 验收

- 包内注释级改动：deps 含该包的图在下次重扫后**保持新鲜**（重盖章），全程零 LLM；
- 真实事实面变化（包增删 / 边表变化 / 实体增删）：对应图照常墓碑重建；
- 旧信封（无 `factsHash`）行为与现状完全一致；
- 全量测试绿；重扫 RPC 时延不被批量重验拖长（时间盒生效，超时转后台）。
