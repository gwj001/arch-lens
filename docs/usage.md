# Arch Lens 使用手册

> 面向使用者：每个 Tab 与交互怎么走一遍。按钮速查表见 [README](../README.md#3-界面速查)。

## 开始之前

- 学习台跟随**左侧栏当前会话**：所有讲解与 AI 生成都发进那个会话。切换会话 = 切换"老师"。
- 一切产物落在**被扫描的工作区**里：缓存 `index/`、你让 AI 写进仓库的文件（一键文档落在
  `docs/architecture-<章>.generated.md`）。讲解的问答与图就在**当前会话历史**里（会话记录 =
  笔记）。旧笔记系已退役（见下节），既有旧笔记文件原样保留、不删不动。
  换工作区（切到别的会话目录）后是全新的一套。

## 推荐的第一次流程

1. 打开学习台 → 等图自动加载（有架构文档的仓库会秒出概念/流程/时序原文，0 费用）；
2. 点 **↻ 重新扫描**（如果代码刚改过）——没变的图不会被重做；
3. 点 **⚡ 变动更新**——只补画失效/缺失的图；
4. 逛 8 个 Tab，对感兴趣的节点 **🗣 AI 讲解**——回答进会话，会话历史就是你的笔记；
5. 想回看讲过什么、画过什么图：直接翻当前会话记录（图也完整保留在里面）。

## 三个扫描 / 重建按钮

顶栏三颗按钮是**全仓批处理**入口（只想补某一张图，去对应 tab 点 🤖 AI 生成）。它们共用
同一套事实（扫描图 + 代码索引 + factsVersion）与同一套版本化缓存，每套工作区各自独立；
区别只在「是否检测代码变化」和「重绘范围」：

| 按钮 | 做什么 | 什么时候用 | LLM 费用 |
| --- | --- | --- | --- |
| ↻ 重新扫描 | 只重建**事实**：重扫代码图与代码索引 → 生成新 factsVersion → 与上次工作区清单比对 → **精确失效**受变动包影响的图缓存。文件没动时直接跳过重建 | 代码改过之后；也是空态/崩溃残留的恢复入口 | **0**（永不生成图） |
| ⚡ 变动更新 | **一条链**：先重新扫描（检测变化 + 精确失效），再智能增量重绘——只补画失效/缺失的图 | 日常改完代码后的一键维护 | 只给失效的图花 LLM；没变化时 0 费用秒回 |
| 🔁 全量重建 | **不**重新扫描，直接对全部注册表图逐一校验缓存（对当前 factsVersion 是否有效/存在）：失效/缺失的重绘，有效的跳过 | 刚扫描过、想把失效/缺失的图一次补齐（缓存被手动删过、首次全量补图等） | 同上：只给失效/缺失的图花 LLM |

要点：

- **「全量」指清点范围，不是重绘范围**：界面上走的是智能增量路径——逐图校验缓存、只重绘
  失效/缺失的图，全部有效时 0 LLM 秒回并提示"已全部最新"。后端保留旧的"无条件全绘"路径
  （`incremental=false`），但界面不再触发它。
- **改完代码直接点 🔁 全量重建会"什么都不画"**：没有重新扫描，缓存对旧 factsVersion 仍然
  有效 → 全部跳过。想让重绘跟上代码变化，用 ⚡ 变动更新（自带重新扫描），或先 ↻ 再 🔁。
- **重新扫描 0 费用、不自动生成任何图**：它只失效缓存；各 tab 懒加载，重新进入页签时才按
  需拉取。崩溃残留（图缺失但文件无变动）会被自动补建并单独提示。
- **方法级（-methods）图不在批处理范围**：按需在对应 tab 用 🔬 + 🤖 生成。
- **空态先扫描**：没有扫描事实时，两颗重建按钮不可用——先 ↻ 重新扫描。
- **可中断、可离开**：生成中 ⏹ 停止随时生效，已完成的图保留；关掉页面后台继续跑，重开
  学习台自动接续显示进度。
- **只读模式预检**：两颗重建按钮在动 LLM 之前先做写入预检，只读会话直接拒绝，不会
  "生成完但缓存写不进"。

## 各 Tab 走读

### ⚡ 总览
全仓一句话 + 一张动态总图。没有图时点 🤖 生成。

### ① 概念树
仓库的分层概念结构（来自文档原文或 AI 归纳）。
- 点击分组节点展开/收起；点击包节点打开详情弹窗（职责 + 核心文件 + 依赖）。
- 🗣 讲解：对概念节点发起讲解（问题带职责/文件/入口源码依据）。
- 右键任意节点 → 标签进入 🎨 出图输入框。

### ② 时序
两个视图：**主流程时序**（业务叙事，10–16 步）与 **调用关系**（谁引用谁的静态边）。
- 🔬 方法级开关：换"方法 + 真实调用边"的证据重新归纳一版。
- hover 任意消息边 → 🤖 动态画图：钻取这两个包之间的方法级时序。
- 右键包节点 → 讲解该组件。

### ③ 流程图
同一流程的**两个视角**：事件驱动 / 数据管道（chip 本地切换，零费用）。
- hover 子图（阶段框）标题 → 🤖 只展开这个子块的细节图。
- 图下方「✏️ 追问重画」：对话框里追加要求（"把校验环节展开"），原图更新；
  旁边 🗣 是先让 AI 讲解当前图，💾 是保存锁定当前版本。

### ④ 交互
事件清单：生产者 → 事件（模式 emit/waterfall/parallel/serial）→ 消费者。
点击事件行看详情；🔬 方法级同上按需生成。

### ⑤ 依赖 / ⑥ ER
只画**核心子图**（AI 挑选 4–25 个关键包 + 真实 import 边 / 实体关系），避免全量毛线团。
对某个包感兴趣就右键 → 🗣 讲解组件。

### ⑦ 目录
所有包的职责一览表：每行职责按 **AI 总结（生成过则优先）→ 中文 README 首段（中文界面）→
package.json description（缺则 README 首段）** 三级兜底；打开即读缓存（零 LLM，部分总结也照常
成表），「🤖 AI 生成职责」才触发分批补齐。**这份 AI 总结同时会进出图 prompt 的「各包职责」段**
（后端组装时直接读版本化缓存，无需打开过目录 tab——职责→出图一条链）。

## 🎨 动态出图

三种打开方式：右键图中元素 / 顶栏入口 / 追问重画。面板里输入你的问题 →
AI 会先出「标题 + 图 + 120–300 字讲解概要」三件套。在出图面板的图上**右键**节点/边/子图标题
会攒成**选中清单**（chips，带图号定域、可多选、✕ 移除）：最终意图 = 选中目标 + 你输入框里的话
（可空）+ 按钮动词（✏️ 重画 / 🗣 讲解），发送成功即清空——不点按钮不花一分钱。动作行：

- **💾 保存当前图（锁定图号）**：成为你的资产，重扫不失效；在"已保存"列表可回看/删除；
- **🗣 AI 讲解**：选中了目标就发**轻量指令**——图号 + 选中目标 + 你的指令（必须填指令，
  为空提示「请输入指令」），不带讲解规则模板，图自己回看会话历史；没选中就讲解整张图
  （完整讲解规则，指令可空）；图源附件同一会话不重复发送，省钱；
- **✏️ 追问重画**：带当前图进对话框，追加要求原地更新；
- **🔧 按报错修复重画**：仅当这张图**渲染失败**时出现——浏览器里的 mermaid 是图有效性的
  唯一裁判，按钮把它的报错原文 + 坏图源码喂回同一会话轮（新 figId nonce、同图号场景，
  **只修语法禁改语义**），修复覆盖原场景。纯手动，不点不花钱；连续 3 次失败后按钮会提示改用重画。

配套防线（都零 LLM）：能确定安全的语法（如裸 subgraph 标题里的半角括号）在捕获与渲染两端
由**同一份**修补器（`mermaid-fix`）免费修好；下钻图渲染失败会自动失效其磁盘缓存（下次打开
走重新生成，不再每次 hover 重复报错）；渲染失败的图**保存会被拦截**，坏图永不落盘。

## 📄 一键生成文档（V1 章节管线）

点「📄 一键生成文档」：后端按 7 章串行生成（**认知主干顺序**）——包目录职责 / 概念层级 /
依赖 / 时序 / 流程图 / 实体关系 / 核心交互，每章一次独立 LLM 调用、独立信封缓存、独立失败重试：

1. **只依据事实写正文**：每章的 prompt 携带同一份代码事实快照（包清单、真实调用边表、
   章节专属事实——概念树/时序/流程图/交互四章还会带上对应 tab 的已生成图）；
2. **幻觉门禁**：生成的正文先与事实快照做零 LLM 比对（编造的带 scope 包名、不存在的文件
   路径、调用关系表里的虚构/反向边），违规即退回**一轮修复**；修复后仍不过关的章节以
   ⚠️ 标记落地（不写缓存，下次重试）；
3. **落地与复用**：每章独立写 `docs/architecture-<章>.generated.md`（文件头带生成来源
   注释，重生成即覆盖）；正文之后附「## 图示」一节——**零 LLM** 从对应图缓存规则渲染
   （流程=原样 mermaid、时序=消息序列图、依赖/ER=核心子图、概念=嵌套列表、交互=事件表），
   文档即"文+图"完整交付物；版本化信封缓存与图缓存同一套机制——代码没变时重复点击
   **只补缺、不重花钱**；
4. **代码变了，旧稿当底稿改**：章节/时序/交互/流程/核心的缓存过期后不再整篇重写，而是把
   旧产物作为「先前稿」喂回，让模型只修订与新事实不符的部分（更快、更稳）；门禁照常复审，
   旧稿里站不住的名称不会被保留。想要彻底从零重写：🔁 全量重建（图）或删除对应信封文件
   （章节）。

注意点：

- **图驱动章节是纯消费者**：概念/时序/流程/交互四章要求对应 tab 已有图缓存，缺图则跳过并
  提示"先去对应 tab 点 🤖 AI 生成补图"，不会替你暗中触发出图（避免一次点击产生意外费用）；
- 依赖/ER/目录三章只靠代码事实就能写，任何仓库都可直接生成；
- 中断随时生效（⏹ 停止），剩余章节记为已中断，再点一次续跑；
- 门禁只拦"有硬证据"的编造（包名/路径/结构化边）；散文里的裸标识符与自由叙述边不在
  V1 拦截范围——生成结果仍建议人工过目。

## 📓 笔记与会话记录（2026-09 调整）

- **会话记录就是笔记**：每次 🗣 AI 讲解的问答、🎨 生成的图、追问过程都完整留在当前
  会话历史里——比旧笔记抄录（只记问答、记不住图）更全。因此旧笔记系
  **已退役**：`📊 学习进度`（教练总结+覆盖度徽章，数据源=笔记文件）与笔记面板不再
  展示，讲解完成后也不再额外抄录笔记。
- 「📄 一键生成文档」已按 V1 章节管线**重做回归**（零 LLM 模板组装的旧实现已删除，
  理由与旧开关式屏蔽一并记在 CHANGELOG）；操作见上节。
- **不受影响的**：讲解功能本身（会话回合、LLM 记账照常）；时序/流程图对仓库既有
  `docs/*.md` 的"逐字提取"读路径（文件在就照常出 `doc` 权威徽章）；你手写的
  `docs/architecture.md` 永远不会被插件覆盖（生成文档一律带 `.generated.md` 后缀）。
- 清空统计/缓存等重资产操作请手动删对应文件（设计如此，防误删）。

## 常见问题

**Q：改了代码，图要重新花钱吗？** 不。↻ 重新扫描 0 LLM；只有依赖了变动包的图会在 ⚡ 变动更新时重画。

**Q：AI 生成的图能信吗？** 看徽章：`doc`/`code` 是原文与真实调用（权威）；`flow` 是归纳，
讲解时 Arch Lens 会把同一份事实依据也发给 AI，并要求它"只依据事实作答、引用出处"。

**Q：怎么不花 LLM 费用先把架子搭起来？** 给仓库写一份带「## 概念」「## 时序」「## 流程」
标题的架构文档——三条链会逐字提取，全 Tab 0 费用冷启动。

**Q：同一工作区换个会话（或开新任务），图和代码事实要重新生成吗？** 不用。图缓存以及
它依赖的代码事实（扫描图 + 代码索引 + factsVersion）都基于**被扫描的工作区**读取与落盘：
缓存写在那个工作区 `index/` 下，同一工作区内的不同会话、不同任务共用同一套版本化缓
存——命中即复用、0 LLM；切换会话只是纯加载、从不失效缓存。换到别的会话目录（别的
工作区 root）才是全新的一套。
